# BALI PHOTO WALL

Отдельный веб-сервис клуба BALI для показа фотографий гостей на LED-экранах. **Не зависит от BALI-MENU, Firebase, Supabase и BALI Staff.** Сделан с нуля, не является форком LiveDrop.

## Возможности

- **/** — мобильная страница гостя: QR → фото → согласие → отправка (без аккаунта).
- **/admin** — вход по паролю, очередь фото, одобрение, отклонение, удаление, создание и смена мероприятия. Старые мероприятия можно открыть для просмотра и удаления снимков, не переключая LED-экран. При больших галереях фото отображаются страницами по 48; клик по миниатюре открывает полный снимок без обрезки.
- **/screen** — полноэкранное слайд-шоу всех одобренных снимков текущего мероприятия (без прежнего ограничения 150 записей); QR-код для гостей. Для просмотра нужен отдельный `SCREEN_PASSWORD`.
- **/healthz** — проверка работы сервера.

Снимки хранятся на диске компьютера клуба в папке `data/photos`, метаданные и статусы — в локальной SQLite `data/bali-photo-wall.sqlite`. Модерация обязательна. У каждого мероприятия своя галерея. Число снимков с одного гостевого браузера настраивается (`MAX_PHOTOS_PER_GUEST`, `0` отключает лимит), с защитой от одновременных отправок, обработка JPEG/PNG/WebP через sharp, максимальный исходный файл 8 МБ. Фото преобразуются в WebP размером до 1600×1600. Старые снимки удаляются через заданное число дней (по умолчанию 7). Это браузерное ограничение, не криптографическая защита от злоумышленника; рекомендуется дополнять его WAF/Turnstile при реальном публичном запуске.

## Быстрая установка на Windows для baliminsk.online

Готова отдельная инструкция **[docs/WINDOWS_SETUP.md](docs/WINDOWS_SETUP.md)**. В ней шаги от распаковки репозитория до публикации QR-кода на LED-экранах.

Для Windows 10/11 с Node.js 22+ предусмотрены четыре файла с запуском двойным кликом:

- `INSTALL-WINDOWS.cmd` — установка зависимостей, создание **локального** `.env` со случайным секретом и двумя разными паролями, `npm audit` и проверка JS.
- `START-WINDOWS.cmd` — запуск сервера клуба на `127.0.0.1:3100` с повторным стартом при аварийном завершении.
- `DIAGNOSE-WINDOWS.cmd` — проверка Node.js, локального сервера, NS домена, публичного HTTPS и службы Cloudflare Tunnel.
- `CONFIGURE-WINDOWS.cmd` — изменение пределов загрузок и сроков хранения без редактирования секретных паролей.

При необходимости `scripts/enable-autostart.ps1` добавляет запуск приложения при входе в Windows. Подключение существующего Cloudflare Tunnel выполняется отдельно через защищённую команду из панели Cloudflare.

**Вся гостевая часть остаётся на `https://baliminsk.online`.** Компьютер клуба является только сервером/источником LED-показа. Основное `baliminsk.by` и BALI-MENU не затрагиваются.

## Запуск на компьютере клуба (Windows / Linux)

Нужен **Node.js 22+**. Сервер должен работать всё время, пока клуб принимает фотографии.

1. Скачать репозиторий или выполнить `git clone https://github.com/Nik13599/BALI-PHOTO-WALL.git`.
2. В папке проекта выполнить `npm install`.
3. Скопировать `.env.example` в `.env`.
4. В `.env` установить **свой** длинный `ADMIN_PASSWORD`, **другой** пароль `SCREEN_PASSWORD` (оба минимум 12 символов), случайный `SESSION_SECRET` (минимум 32 символа), `PUBLIC_URL=https://baliminsk.online`.
5. Выполнить `npm start`. Для самопроверки: `npm run check`. Автоматические интеграционные проверки хранятся в `tests/smoke.test.mjs`. Полная проверка проекта: `npm test` (изолированная временная база данных, рабочие фотографии не затрагиваются). Есть тест галереи на 300 фото и проверка авторизации на локальном компьютере в режиме production.
6. На этом же компьютере открыть `http://127.0.0.1:3100/admin` и `http://127.0.0.1:3100/screen`.

При `NODE_ENV=production` локальные служебные страницы доступны на `http://127.0.0.1:3100`, а при обращении по публичному домену cookie помечаются `Secure`. Никогда не публикуйте `.env` в GitHub.

Пример генерации случайного секрета: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.

## Подключение к baliminsk.online (Cloudflare подготовлен)

На 23 октября 2026 г. в Cloudflare уже создана зона `baliminsk.online` (тариф Free), проксируемая CNAME-запись и **удалённо управляемый Tunnel** с названием `bali-photo-wall`. Создавать ещё один туннель и вызывать `cloudflared tunnel route dns` **не нужно**.

Статус зоны при настройке: **pending**. У регистратора `baliminsk.online` требуется выставить два NS Cloudflare:

- `eric.ns.cloudflare.com`
- `kehlani.ns.cloudflare.com`

Существующий `baliminsk.by` в отдельной зоне и не изменялся. До переноса NS проверьте наличие других используемых записей у регистратора, например почтовых MX: при смене NS их надо сохранить в Cloudflare.

### Запуск туннеля на компьютере BALI

1. Сначала установите Node.js 22+ и запустите сервер по инструкции выше: `npm install`, заполнение `.env`, `npm start`.
2. В панели Cloudflare откройте **Zero Trust → Networks → Connectors / Tunnels → bali-photo-wall**.
3. Выберите **Add connector / Install connector**, операционную систему компьютера клуба и скопируйте **персональную** команду установки и запуска `cloudflared`, которую выдаст Cloudflare. Она содержит секретный токен: не публикуйте его в GitHub или переписке.
4. Запустите эту команду на компьютере клуба с правами, требуемыми установщиком. Для постоянной работы лучше установить `cloudflared` как службу.
5. Убедитесь, что туннель перешёл в статус **Healthy**, а зона домена Cloudflare — в статус **Active**.
6. Проверьте `https://baliminsk.online/healthz`, затем загрузку реального снимка, модерацию по `/admin` и показ по `/screen`.

**Настроенный ingress:** `baliminsk.online → http://127.0.0.1:3100`, остальные запросы к туннелю получают 404. DNS уже настроен на этот туннель. Никакого публичного IP-адреса на компьютере клуба не требуется.

Полезная документация: [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/).

## Новые ограничения после аудита

- Подписи сессий разделены по ролям `guest`, `screen` и `admin`. Старые cookies автоматически становятся недействительными, поэтому после обновления понадобится повторно войти.
- При переключении активного мероприятия фотография, обрабатываемая в момент переключения, не попадёт в старую галерею: пользователь получит предложение повторить отправку.
- `MAX_PHOTOS_PER_EVENT=0` отключает фиксированный лимит снимков на мероприятие. `MAX_PHOTOS_PER_GUEST=3` задаёт лимит на гостевой браузер (0 отключает). `UPLOAD_REQUESTS_PER_HOUR=0` отключает часовую квоту запросов. Все три параметра можно поменять двойным кликом по `CONFIGURE-WINDOWS.cmd`, после чего перезапустить сервер.
- `MIN_FREE_DISK_MB=512` останавливает загрузку, когда заканчивается место. `MAX_ACTIVE_UPLOADS=12` ограничивает число параллельных операций, чтобы не перегружать компьютер. Эти защитные ограничения не являются платными квотами и тоже настраиваются.
- Снимки продолжают автоматически удаляться через 7 дней (значение `RETENTION_DAYS`). Количество запросов не тарифицируется по модели Firebase/D1/R2, но ограничено скоростью компьютера, интернета и условиями Cloudflare Tunnel.
- Аварийно оставленные промежуточные и обработанные файлы очищаются автоматически после защитного периода; модератор может удалить фото вручную.
- Если LED-экран три раза подряд не может получить актуальный список фотографий, старый показ скрывается и появляется сообщение о потере соединения.
- Зависимости `multer` (2.4+) и `sharp` (0.35.5+) обновлены для устранения известных уязвимостей. `npm audit` теперь включён в GitHub Actions.

## Безопасность и ограничения

- Библиотека загрузки Multer требует версии `2.4.0` или выше в диапазоне 2.x, так как старые версии содержали опубликованные уязвимости отказа в обслуживании. GitHub Actions проверяет production-зависимости командой `npm audit --omit=dev --audit-level=high`.
- На мероприятиях с сотнями фотографий LED-экран получает все одобренные снимки (вместо прежних первых 150), а панель модератора использует постраничный вывод по 48 карточек.

- Сервер по умолчанию слушает только `127.0.0.1`, не открыт напрямую в интернет.
- Панель админа защищена паролем, подписанной HttpOnly cookie на 12 часов и дополнительным заголовком на изменяющих запросах.
- Доступ к снимкам (даже одобренным) требует отдельной авторизации оператора экрана или администратора. Без авторизации API фотографий отвечает 401; неодобренные фото не показываются на LED-экране.
- В обработанных фотографиях не сохраняются EXIF-метаданные, но лица и другие персональные данные на самих фото могут оставаться.
- Локальные файлы не бэкапятся автоматически: настройте резервные копии и корректное выключение компьютера. Для доступа к панели по адресу `http://127.0.0.1:3100/admin` Secure-флаг cookie не ставится; на публичном HTTPS-домене применяется Secure.
- Рекомендуются явные правила показа и удаления снимков, отдельный контакт для удаления и ручная модерация.
- Для стабильной работы 800 одновременных гостей нужен нагрузочный тест на оборудовании и интернете клуба. Ограничение частоты загрузок применяется к IP-адресам; на общем Wi-Fi посетители могут делить один внешний IP.
- Анонимную загрузку можно использовать только с дополнительными ограничениями на уровне Cloudflare (например, Turnstile или WAF). Настраиваемое ограничение снимков на браузер не является надёжной защитой от ботов. Бесплатность зависит от использования уже имеющегося компьютера, интернета и домена.
- GitHub Pages **не подходит** как сервер этого приложения: требуется Node.js с доступом к диску.

## Проверка

`npm run check` — базовая проверка синтаксиса JS.
`GET /healthz` — ответ `{"ok":true}` если сервер запущен.
`data/` и `.env` исключены из Git благодаря `.gitignore`. Временные оригиналы фотографий размещаются на диске, а не в оперативной памяти; после обработки удаляются. Оставшиеся после прерывания загрузки временные файлы удаляются автоматически, если им более 2 часов.

В репозитории находится код приложения; **публикация в интернет не выполняется одним коммитом**. Нужно запустить Node.js и Cloudflare Tunnel на компьютере клуба.
